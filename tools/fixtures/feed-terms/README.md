# feed-terms fixture

規約 1 本を引き当てる経路 (item → terms_ref → terms チャンク) を **end-to-end** で測るための
ミニチュアフィード。パーサ単体は `tools/fixtures/seed-terms/` の実レコードで測れるが、**配線**
(署名検証を通ったキャッシュから正しいチャンクを選んで読むところ) はフィードの形でしか測れない。

- 中身は**実レコード**: `seed-terms/18de8a92.json` (RadDollV3 の規約) をフィード生成器の
  `terms_chunk()` で配信形にしたものと、それを参照する item 3741802。模式データにしないのは、
  キー名の食い違いを検出できなくなるため (過去に実際に起きた事故と同じクラス)。
- この規約は `matrix_overrides` を 1 件持つ = **行字義 (allowed) と実効値 (conditional) が食い違う**。
  2 層が別々に届いていることを、この差で測る。
- `keyring.json` の鍵は**使い捨て**で、秘密鍵は署名を検証した直後に破棄済み。
  したがって**この fixture に新しい署名を足すことはできない** — 世代を増やすなら鍵ごと作り直す。
- `tools/fixtures/feed-cache/` と分けてあるのは、あちらも同じ理由で署名を足せないため。
  既存テストの期待値を 1 つも動かさずに経路を増やす手段が、別 fixture しかない。
- `index.json` は署名対象そのもの。**1 バイトも変えてはいけない**
  (`.gitattributes` の `tools/fixtures/** -text` が改行変換を止めている)。
- 書式はフィード生成器 (非公開の収集パイプライン) の `canon_bytes` と同一
  (キー順固定 / 非 ASCII をエスケープしない / indent=1 / 末尾改行)。
